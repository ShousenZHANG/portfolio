法律业务数据分析智能问数 Agent | AI Agent 开发 | 2025.07 – 2026.09
项目技术栈：GPT + Claude + Python + LangGraph + Milvus + Elasticsearch + MySQL + Embedding
项目背景：律所数据仓库汇集法律咨询中心、案件管理、SAP、客户关系、工时管理等系统数据，全所 2000 名律师及案件运营、财务、合规人员取数需向数据团队提需求、等待排期。本项目构建以数仓元数据强约束的 NL2SQL 智能问数 Agent，业务人员用自然语言即可自助完成多维度数据查询、指标统计与排名分析。
工作描述：
1. 数仓元数据知识库建设系统设计与实现：通过配置化文件定义同步范围，自动化抽取案件、客户、财务、工时、合规等核心业务域的事实表、维度表结构、字段属性、业务指标定义与字段枚举值等元数据，支持增量同步与版本管理。
2. 多源异构元数据汇聚与向量索引构建：覆盖全所全链路表结构、字段业务含义、核心指标口径与字段真实取值；利用 Embedding 构建基于 Milvus 的字段与指标语义向量库，同时基于 Elasticsearch 搭建字段取值全文索引。
3. 多引擎混合检索召回机制设计与实现：融合 Milvus 语义向量检索、Elasticsearch 全文检索与 MySQL 结构化查询，基于分词能力抽取业务关键词后，并行召回字段、指标、字段取值三类信息；叠加律所业务域（案件/客户/财务/合规）维度过滤。
4. RAG 与 Agent 核心逻辑研发：基于 LangGraph 搭建完整 NL2SQL 可观测工作流，编排关键词抽取、多路并行召回、召回结果合并、无关表与指标二次过滤、环境上下文增强全节点执行链路，每一步执行状态与中间明细可追溯。
5. SQL 生成-校验-纠错闭环：约束大模型仅基于召回的真实表字段生成 SQL，用数仓 EXPLAIN 校验语法与执行可行性，校验失败时将报错回传模型自动修正，从源头抑制幻觉 SQL。
项目成果：
- 取数方式转变：常规数据查询从提需求、等数据团队按天排期，转为业务人员用自然语言自助查询、分钟级拿到结果，数据团队从重复取数中释放出来。
- 结果可信可审计：SQL 只基于召回的真实表字段生成，经 EXPLAIN 校验、失败自动纠错；指标按元数据中的官方口径计算，输出可直接用于经营分析与合规审计。
